Prometheus. Confirm it is actually scraping before blaming an empty panel:

  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "b2c-observability.prometheus.fullname" . }} 9090:{{ .Values.prometheus.service.port }}
  curl -s 'http://localhost:9090/api/v1/targets?state=active' | grep -o '"health":"[a-z]*"'

A target stuck "down" usually means the address does not resolve: it is a
Service name in this namespace, and the b2c-api chart names its Service after
its release. Check with `kubectl -n {{ .Release.Namespace }} get svc`, then:

  helm upgrade {{ .Release.Name }} ./helm/b2c-observability \
    --set scrapeTargets[0].address=<service>:9464
{{- end }}

Panels stay empty until the API has served something. The demo links on the web
app's home and welcome pages generate both outcomes; the rejection panels fill
in from the 401s.
